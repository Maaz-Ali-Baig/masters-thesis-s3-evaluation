PREDICTIONS COMPARED
P-SEC-1 "SSE-S3 is refused, SSE-C is supported": the SSE-S3 half is WRONG (the upload with --sse AES256 was accepted, and the content is stored readable); the SSE-C half is right as far as accepted (the answer carries
        the SSE-C fields) and its marker is not found in clear (not read back with the key, see Q1).
P-SEC-2 "blocks are compressed with zstd, random padding and a positive control are needed": right (blocks are .zst files, the plain control is found with random padding).
P-SEC-3 "port 3902 answers /health and /metrics without a token, other admin calls need the token": right (all /v1 calls and the POST gave 403).

PROVEN
------
G-P1. The S3 port refuses anonymous access (PUT, DELETE, no signature, wrong secret, fake key) with 403 / AccessDenied on every node tested; Garage tells "Invalid signature" and "No such key" apart in its answers.
G-P2. Port 3902 is an HTTP interface on every node: /health and /metrics answer without credentials (the metrics text is 194 to 395 KB), all /v1 calls (and a POST that would create a key) are refused with 403.
G-P3. A key limited to read on one bucket can list and read that bucket only; write, delete, creating a bucket and reading another bucket are refused (403), and the bucket list shows only its own bucket.
G-P4. Object content crosses the network in clear on the S3 port (plain http, no TLS configured): 199 of 200 marker lines in the capture.
G-P5. Content uploaded with the SSE-S3 header is accepted and stored in clear (marker found in a .zst block file on every node, as for the plain control). So an SSE-S3 request gives no protection at rest.
G-P6. Content uploaded plain is stored in clear in block files on every node (three copies), zstd compression does not hide a marker in incompressible random data.
G-P7. A failed login with a fake key is visible in the log of the node that served it (2 lines on ceph0, 0 on the others).

NOT PROVEN, open
----------------
Q1. SSE-C: the marker is not found in clear on any node, but that alone does not prove encryption (an object that was not stored, or stored compressed, gives the same result). Settles: read the object back with the
    right key and without the key, and look at the size of the block file. Not done.
Q2. What the 2 log lines on ceph0 contain (key id, source address, reason). Not read.
Q3. Ports 631 (all nodes) and 3901 (RPC between the nodes) were not tested for anonymous access; 3901 is the cluster RPC, authentication with the shared rpc_secret is not tested.
Q4. Whether the metrics text on 3902 (about 0.2 to 0.4 MB) contains anything sensitive (bucket names, key ids). Not read.
Q5. Whether the anonymous 3902 /metrics is a default of Garage or the result of the configuration of this setup (the configuration file was not re-read for this record).

LIMITS
------
L1. One run per check, one cluster, plain http only. No TLS test (none configured). The sec4 run 1 and the sec6 run 1 are kept as records of the first attempt, their results are not used as findings except where stated.
L2. sec2 made no anonymous write test because no non S3 port answered 200 or 3xx on "/"; the admin port was tested by hand with a few paths only.
L3. No comparison between systems is made in this record.
