PROVEN (quoted lines in the raw file)
-------------------------------------
1. Ceph 20.2.4 rejects all eight unsigned cases, p1 to p8, with 403 AccessDenied. That includes every
   x-amz header that RustFS accepted and applied.
2. The rejection is caused by the header not being signed, not by the header itself and not by the request
   shape. With nothing extra (p0) the same PUT is accepted, and with the metadata header inside the signature
   (s2) it is accepted and applied ("x-amz-meta-injected: yes" in the headers read back). Only the signing
   of the header differs between p2 and s2.
3. The test can detect an applied header on Ceph. In the control s3, where x-amz-acl: public-read is part of
   the signature, an anonymous GET returns 200 on an object that p0 and s2 leave private (403). So Ceph
   applies the ACL header when it is signed, and refuses the same header when it is not (p3).
4. The signing code is correct on Ceph: g0 (presigned GET) and p0 are 200.
5. Ceph also rejects an unsigned Content-Type (p1), as in the compatibility and Warp results. The other
   three systems accept it and apply it. AWS tolerates an unsigned non x-amz header, so Ceph is the
   strictest of the four here.
