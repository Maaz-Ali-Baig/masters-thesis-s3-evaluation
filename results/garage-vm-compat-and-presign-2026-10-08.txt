HYPOTHESIS H3 (untested): the 403 on the ACL read is caused by the client on ceph0, not by Garage. Reasons for
suspicion: the same request signs correctly with curl 8.5.0 on the laptop (501, the answer comes after the
signature check), curl on ceph0 is 7.88.1, and the Ceph record has the same open point (O6, ACL read fails on Ceph
from ceph0). The ACL request is the only one with a query parameter without a value (?acl). Settling test: send
the ACL read with the AWS CLI on ceph0 (s3api get-object-acl). If Garage answers 501 NotImplemented, the curl
signing on ceph0 is the cause and the same applies to Ceph O6.
